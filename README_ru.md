Софт для создания туннелей к камере Dahua (по серийнику) и форвардит любой порт на localhost через облачный протокол Dahua HTTP P2P. По сути — улучшенная версия DH-P2P.

## Улучшения 

- Поддерживает форвардинг **нескольких портов сразу**
- **Декодер пакетов** (`--decode`) — разбирает пойманные пакеты офлайн (DH HTTP, инвертированный STUN, PTCP).
- Отправляет **heartbeat**  и **RTSP keepalive** для поддержки туннеля

## Сборка

```sh
git clone https://github.com/Mamkabesa/dh-fwd
cd dh-fwd
go build .
```

## Как пользоваться

```
./dh-fwd [options] <serial>
```
**Или:**
```
./dh-fwd <serial> [options]
```
## Известные баги

• Не работает вход через браузер (ответ камеры: "Ошибка входа!" или "Login error!" в зависимости от локализации), из-за чего может временами отваливаться соединение по 80 порту

## В процессе разработки
• Поддержка входа к камере которая требует Type 1 Auth
• Фикс некоторых багов
• Поддержка входа к камере по порту 80

### Флаги

| Флаг | Короткий | Что делает |
|------|----------|----------|
| `--debug` | `-d` | подробный отладочный вывод протокола (запросы, STUN-пакеты, PTCP-фреймы) |
| `--log-retries` | `-lr` | лог ретраев с таймштампом |
| `--port` | `-p` | порт, см. ниже |
| `--threads` | `-mt` | кол-во потоков (по умолчанию 3) |
| `--decode` | `-D` | декодер пакетов |
| `--decode-type` | `-T` | что декодировать: `auto`, `dhttp`, `istun`, `ptcp` (по умолчанию `auto`) |

`--help`/`-h` выводит список команд.

### Как указывать порты (`--port`)

Есть 2 порта - локальный (который мы будем слушать) и внешний (который камера нам отдает).
Слева - локальный, справа - внешний.
Если указан только один порт (пример: -p 80) - открывается порт 80 на ЛЮБОМ свободном порте.

Примеры ввода:

- `-p 5080,5081,5082:80,81,82` — явные пары «локал:камера», один к одному;
- `-p 8080,8081,8082:80` — несколько локальных портов на один внешний;
- `-p 80-85` — диапазон портов;
- `0:81` — порт `0` означает «любой свободный в системе»;
- если порт не указан — открывается порт 554 по дефолту.

Локальные порты открываются на `127.0.0.1`.

**Важно:** если вы запускаете софт без флага -p или указываете слушаемый порт <1024 и прога не запущена с sudo, возможна ошибка 
```sh
Tunnel failed, reason - no listeners available for tunnel
```
### Режимы работы

**Single** — форвардит только 1 порт 
```sh
./dh-fwd SN -p 5080:80
```

**Multi** — форвардит несколько портов одновременно. Срабатывает автоматически, если портов несколько, или если включена многопоточность
```sh
./dh-fwd SN -p 5080,5081:80,81 -mt 4
```
```
Opening 2 ports on SN | Threads: 3
[..] Opening SN:80 | Connecting...
[OK] Obtained SN:80 -> 127.0.0.1:5080
[OK] Obtained SN:81 -> 127.0.0.1:5081
Obtained 2 ports on SN:80,81 | localhost:5080,5081
```

**Decode** — разбирает пойманный пакет без подключения к камере:
```sh
./dh-fwd -D -T ptcp <hex>
./dh-fwd -D -T auto 0x... 0x...
echo '<hex>' | ./dh-fwd -D
```
## Что такое Dahua P2P?

Это проприетарный облачный протокол Dahua, который используется для соединения с камерами по облаку, даже если камера находится хоть за 3мя NAT. Работает это +- так: клиент (SmartPSS, или dh-fwd) отправляет запрос на главный сервер -> получает промежуточный сервер -> создаёт канал связи -> пытается пробить NAT (если он симметричный) -> поднимаем туннель -> PROFIT.

**Важно:** До **2025 года** P2P-сервера Dahua поднимали туннель *без аутентификации*. После всей шумихи с дырявостью протокола, все устройства, выпущенные **после второй половины 2024 года**, запрашивают аутентификацию **до** установки туннеля.

## Режим Decode

Флаг `-T` задаёт, какой слой разбирать, а `auto` определяет его сам по первым 4 байтам (магии):

- **`dhttp`** — DH HTTP-over-UDP: метод, путь, статус, заголовки и XML-тело в читаемом виде. Понимает и «голый» HTTP (`GET`/`POST`/`HTTP`), и вариант с префиксом `DH`.
- **`istun`** — инвертированный STUN: разворачивает инверсию и показывает тип сообщения (Binding Request/Response/Error), transaction ID и атрибуты — `MAPPED-ADDRESS`, `XOR-MAPPED-ADDRESS` (с расшифровкой xor), `USERNAME`, `REALM`, `NONCE`, `MESSAGE-INTEGRITY`, `FINGERPRINT`.
- **`ptcp`** — заголовок PTCP-фрейма целиком плюс разбор тела по типу: `0x00 SYNC`, `0x10 DATA` (реалм + payload строкой или hex), `0x11 BIND`, `0x12 STATUS`, `0x13 HEARTBEAT`.

Удобно для реверса и отладки: поймали пакет на сокете (например, `tcpdump`), скормили его `dh-fwd -D -T auto <hex>` — получили разбор.
